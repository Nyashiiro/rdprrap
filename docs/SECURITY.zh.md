## 报告漏洞

**请勿通过公开的 GitHub issue 报告安全漏洞。**

请通过 [GitHub Security Advisories](https://github.com/kernalix7/rdprrap/security/advisories/new) 提交。

### 报告应包含的内容

1. **说明** —— 对漏洞的清晰描述
2. **复现步骤** —— 重现该问题的详细步骤
3. **影响** —— 该漏洞的潜在危害
4. **受影响组件** —— rdprrap 中受影响的具体 crate／DLL
5. **环境** —— Windows 版本、架构（x64/x86/ARM64）、`termsrv.dll` 版本

### 响应时间表

- **确认收到** —— 报告提交后 48 小时内
- **初步评估** —— 7 天内
- **修复与披露** —— 与报告者协商确定；严重问题通常 30 天内完成

### 适用范围

- `unsafe` 块中的内存安全违规
- DLL 劫持／加载路径类漏洞
- PE 解析或反汇编过程中的缓冲区溢出
- 挂起／恢复线程过程中的竞态
- WriteProcessMemory 定位到错误地址
- 通过 wrapper DLL 提升权限

### 非适用范围

- 需要物理接触用户设备才能触发的问题
- 社会工程学攻击
- 第三方依赖中的问题（请向相应上游报告，但也请告知我们）

## 安全最佳实践

rdprrap 遵循以下安全实践：

- 所有 `unsafe` 块均以 `// SAFETY:` 注明不变条件
- 禁止未做边界校验的原始指针算术
- DLL 加载限制在 system32 路径（`LOAD_LIBRARY_SEARCH_SYSTEM32`）
- 挂起线程时采用基于快照的枚举，以防 TOCTOU 竞态
- 发布前运行 `cargo audit`
